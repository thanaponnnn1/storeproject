# ระบบคลังสินค้า + ซื้อ-ขายครบวงจร

ระบบจัดการคลังสินค้าและเอกสารซื้อ-ขายสำหรับ **ร้านเครื่องใช้ไฟฟ้า อุปกรณ์ช่าง และวัสดุก่อสร้าง**
ใช้งานได้จริงหน้าร้าน — ยิงบาร์โค้ดด้วยมือถือรับ-จ่ายของ ตามตัวเครื่องด้วย serial เช็คประกันให้ลูกค้าได้ทันที

```
ซื้อ → รับเข้าคลัง → สต๊อก → ขาย → ส่งของ → วางบิล → เก็บเงิน → รู้กำไร
```

## ทำไมถึงออกแบบแบบนี้

ระบบคลังพังกันบ่อยที่ 3 จุด โปรเจกต์นี้ตั้งใจแก้ตั้งแต่ออกแบบ:

### 1. ยอดสต๊อกห้าม UPDATE ตรง ๆ (ledger pattern)

`stock_movements` เป็นตาราง **append-only** — แก้ไม่ได้ ลบไม่ได้ ไม่มี endpoint ให้แก้ด้วยซ้ำ
ยอดคงเหลือจริงคือ `SUM(movements)` ส่วน `stock_balances` เป็นแค่ cache ที่อัปเดตใน transaction เดียวกัน

คีย์ผิดแล้วแก้ยังไง? → **กลับรายการ (reversal)** ลงรายการใหม่ที่หักล้างกัน รายการเดิมยังอยู่ตลอดไป
มี `GET /inventory/reconcile` ตรวจว่า cache ตรงกับ ledger เสมอ และ cron รันทุกตี 2

### 2. สองคนขายของชิ้นเดียวกันพร้อมกัน

ทุกการรับ-จ่ายทำใน transaction ที่ **`SELECT ... FOR UPDATE`** ล็อกแถวยอดคงเหลือก่อน
คนที่สองต้องรอคนแรก commit แล้วเห็นยอดล่าสุดเสมอ

> ทดสอบจริง: ยิงจ่าย 50 request พร้อมกัน — ยอดคงเหลือตรงเป๊ะ ไม่ติดลบ ไม่มี deadlock

### 3. ต้นทุนต้องตรงกับของที่ออกไปจริง

FIFO ใช้ **cost layers** — จ่ายออกกินล็อตเก่าสุดก่อน บันทึกไว้ว่าของที่ขายไปมาจากล็อตไหน ทุนเท่าไหร่
ตรวจย้อนหลังได้ทุกบิล และรายงานกำไรอ่านจากต้นทุนจริงที่ออกจากคลัง ไม่ใช่ทุนเฉลี่ยปัจจุบัน

> สินค้าที่ติดตามเป็นล็อต (ปูน/สี) จ่ายแบบ **FEFO** ใกล้หมดอายุออกก่อน ซึ่งอาจสวนทางกับลำดับรับเข้า
> ระบบจึงผูกต้นทุนกับล็อตที่จ่ายจริง ไม่ใช่ล็อตที่รับเข้าก่อน

## ความสามารถ

### สินค้า 3 แบบตามธรรมชาติของร้าน

| ประเภท | ตัวอย่าง | ระบบทำอะไรให้ |
|---|---|---|
| **ตามเครื่อง (SERIAL)** | แอร์ ตู้เย็น ปั๊มน้ำ | ยิง serial ทุกเครื่องตอนรับ-จ่าย · **ยิง serial แล้วรู้ทันทีว่าใครซื้อ ประกันเหลือกี่วัน** |
| **ตามล็อต (LOT)** | ปูน สี เคมีภัณฑ์ | เลขล็อต + วันหมดอายุ · จ่ายแบบ FEFO · เตือนล่วงหน้า 30 วัน |
| **นับจำนวน (NONE)** | น็อต ท่อ อุปกรณ์ทั่วไป | นับจำนวนปกติ |

### หลายหน่วยนับ

เหล็กขายเป็นเส้นหรือมัด (1 มัด = 10 เส้น) สายไฟขายเป็นเมตรหรือม้วน (1 ม้วน = 100 เมตร)
สต๊อกเก็บ**หน่วยฐานเสมอ** — ยิงบาร์โค้ดมัดได้ราคามัด ระบบแปลงหน่วยและทุนให้เอง
จำนวนเป็นทศนิยม 3 ตำแหน่ง (สายไฟ 12.5 เมตรได้)

### ราคา 3 ระดับ

ปลีก / ช่างประจำ / โครงการ — ผูกกับลูกค้า เปิดบิลแล้วราคาขึ้นเอง
**พนักงานขายแก้ราคาหน้าบิลไม่ได้** ต้องผู้จัดการขึ้นไป และบันทึก audit ทุกครั้ง

### เอกสารครบวงจร + state machine

```
ฝั่งขาย   ใบเสนอราคา → ใบสั่งขาย → ใบส่งของ ─┐
ฝั่งซื้อ    ใบสั่งซื้อ → ใบรับของ ──────────┤
                                          ▼
                              📒 stock_movements (ledger)
                                          ▼
       ใบส่งของ → ใบแจ้งหนี้ → รับชำระ    ต้นทุน · ยอดคงเหลือ · กำไร
```

- เปลี่ยนสถานะนอกตารางที่กำหนดไว้ไม่ได้ (ประกาศไว้ที่เดียวใน `state-machine.ts`)
- **ส่ง/รับบางส่วนได้** — สั่ง 100 ส่ง 60 ก่อน ระบบคุมยอดค้างรายบรรทัด
- **ยกเลิกเอกสารที่ยืนยันแล้ว = กลับรายการใน ledger** ไม่ใช่ลบทิ้ง
- เลขรันเอกสารไม่ซ้ำไม่โดด (`FOR UPDATE` บนตัวนับ — ทดสอบยิง 30 ใบพร้อมกัน)
- เงินก้อนเดียวตัดได้หลายใบแจ้งหนี้

### บันทึกทุกการเปลี่ยนแปลง

ใครทำอะไร กับอะไร เมื่อไหร่ จาก IP ไหน — **ปิดบังรหัสผ่านอัตโนมัติ** และไม่บันทึกการอ่านข้อมูล (ไม่ให้ log ท่วม)

### รายงาน

มูลค่าสต๊อก **ณ วันใดก็ได้** (คำนวณจาก ledger ย้อนหลังได้) · กำไรขั้นต้นรายสินค้า · ยอดขายรายเดือน · ลูกหนี้แยกช่วงอายุหนี้ · สินค้าต่ำกว่าจุดสั่งซื้อ

### งานอัตโนมัติ

ตี 2 ตรวจกระทบยอด · ตี 1 ใบเสนอราคาหมดอายุ · 8 โมงแจ้งของใกล้หมด/ล็อตใกล้หมดอายุ/หนี้เกินกำหนด · ทุกชั่วโมงล้าง token

## เริ่มใช้งาน

### สิ่งที่ต้องมี

Node.js ≥ 20 · pnpm · Docker Desktop

### 1. ฐานข้อมูล

```bash
docker compose up -d
```

Postgres จะรันที่ port **5433** (เลี่ยง 5432 ที่มักมีของเดิมอยู่)

### 2. หลังบ้าน

```bash
cd backend
pnpm install
cp .env.example .env      # แล้วเปิดแก้ค่าตามด้านล่าง
pnpm migrate              # สร้างตาราง
pnpm seed                 # ข้อมูลตั้งต้น + ผู้ใช้
pnpm build && pnpm start:prod
```

ค่าที่ต้องใส่ใน `backend/.env` (ที่เหลือใช้ค่าใน `.env.example` ได้เลย):

```ini
JWT_SECRET=            # อย่างน้อย 32 ตัวอักษร (app ไม่ยอม start ถ้าสั้นกว่านี้)
SEED_ADMIN_PASSWORD=   # รหัสผ่าน admin ตอน seed

# ไม่ใส่ก็รันได้ แต่ฟีเจอร์อัปโหลดรูปสินค้าจะปิดอยู่
CLOUDINARY_CLOUD_NAME=
CLOUDINARY_API_KEY=
CLOUDINARY_API_SECRET=
```

API อยู่ที่ `http://localhost:3009/api` · เอกสาร API ที่ **`/api/docs`** (Swagger)

### 3. หน้าบ้าน

```bash
cd frontend
pnpm install
pnpm dev                  # http://localhost:3001
```

ไม่ต้องตั้งค่าอะไรเพิ่ม — ถ้า backend ไม่ได้อยู่ที่ `http://localhost:3009/api` ค่อยสร้าง `frontend/.env.local` แล้วใส่ `BACKEND_URL=`

### 4. ข้อมูลตัวอย่าง (ไม่บังคับ)

```bash
cd backend
pnpm demo:products        # สินค้าจริงหน้าร้าน 20 รายการ พร้อมสต๊อก
pnpm demo:barcodes        # ออก PDF ป้ายบาร์โค้ดไว้พิมพ์ทดสอบ
pnpm demo:receive         # สินค้าอีก 10 รายการ (ยอด 0) + ใบสั่งซื้อรอรับของ
pnpm demo:serials         # ป้าย serial ไว้ทดสอบสินค้าที่ติดตามรายเครื่อง
```

### บัญชีทดสอบ

| อีเมล | สิทธิ์ | ทำอะไรได้ |
|---|---|---|
| `admin@store.local` | ผู้ดูแลระบบ | ทุกอย่าง |
| `manager@store.local` | ผู้จัดการ | อนุมัติเอกสาร ปรับยอด แก้ราคา ดูรายงาน |
| `sales@store.local` | ฝ่ายขาย | เปิดใบเสนอราคา/ใบสั่งขาย เพิ่มลูกค้า |
| `warehouse@store.local` | ฝ่ายคลัง | รับ-จ่ายของ ดูสต๊อก |

รหัสผ่าน = ค่าที่ตั้งใน `SEED_ADMIN_PASSWORD`

## 📱 ใช้กล้องมือถือสแกนบาร์โค้ด

**iPhone/iPad จะไม่เปิดกล้องให้เว็บที่ไม่ใช่ https** — ต้องทำ 3 ขั้นนี้

### 1. สร้างใบรับรอง (ทำครั้งเดียว / ทำใหม่เมื่อเปลี่ยน WiFi)

```bash
cd frontend
pnpm cert
```

สคริปต์หา IP ของเครื่องในวง WiFi ให้เอง แล้วออกใบรับรองที่ครอบคลุม IP นั้น
— ถ้าใบรับรองมีแต่ `localhost` มือถือจะเปิดไม่ได้

### 2. เปิด firewall (Windows, ทำครั้งเดียว — ต้องรัน PowerShell แบบ Administrator)

```powershell
New-NetFirewallRule -DisplayName "Store dev 3001" -Direction Inbound `
  -LocalPort 3001 -Protocol TCP -Action Allow -Profile Private
```

`-Profile Private` = เปิดเฉพาะเน็ตบ้าน/ร้าน ไม่เปิดตอนต่อ WiFi สาธารณะ

### 3. รันแบบ https แล้วเปิดจากมือถือ

```bash
pnpm dev:https
```

ต่อ WiFi วงเดียวกับคอม → เปิด Safari ไปที่ที่อยู่ที่ `pnpm cert` บอก (เช่น `https://192.168.1.37:3001`)
→ Safari เตือนเรื่องใบรับรอง กด **แสดงรายละเอียด → เข้าชมเว็บไซต์นี้** → เมนูสแกน → อนุญาตกล้อง

> **แนะนำ:** ปุ่มแชร์ → *เพิ่มไปยังหน้าจอโฮม* จะได้ไอคอนเปิดเหมือนแอป

### ยิงอะไรได้บ้าง

| ยิง | ได้อะไร |
|---|---|
| บาร์โค้ดสินค้า (EAN-13 จากโรงงาน) | ชื่อ ยอดคงเหลือ ราคา |
| บาร์โค้ดของลัง/มัด | แปลงหน่วยให้ (120 เส้น = 12 มัด) พร้อมราคาต่อมัด |
| QR ที่ร้านพิมพ์เอง | เหมือนบาร์โค้ดปกติ (สำหรับเหล็ก ท่อ ปูน ที่ไม่มีบาร์โค้ดโรงงาน) |
| Serial บนตัวเครื่อง | ซื้อวันไหน ใครซื้อ **ประกันเหลือกี่วัน** |

**2 โหมดการยิง** — *ยิงต่อเนื่อง* (เร็ว เจออะไรอ่านเลย) และ *กดแล้วยิง* (เล็งให้ตรงก่อนค่อยกด กันอ่านผิดตัวเวลามีหลายบาร์โค้ดติดกัน)
โหมดกดแล้วยิงรับปุ่ม Enter/Space จากแหวนสแกนหรือชัตเตอร์ Bluetooth ได้ด้วย

> ⚠️ ปุ่มเพิ่ม/ลดเสียงของ iPhone ใช้เป็นปุ่มยิงไม่ได้ — iOS ไม่ส่ง event ปุ่มเสียงให้หน้าเว็บ

**กล้องใช้ไม่ได้?** ทุกหน้าสแกนมีช่องพิมพ์รหัสด้วยมืออยู่ใต้กล้องเสมอ — บาร์โค้ดเลอะ ฉลากขาด กล้องพัง ก็ทำงานต่อได้

## การทดสอบ

ทุกเฟสมีชุดทดสอบที่**ยิงกับระบบจริง** ไม่ใช่ mock และตรวจ**ตัวเลขจริง** ไม่ใช่แค่ status code

```bash
# เปิด backend + frontend ไว้ก่อน แล้ว
cd backend  && pnpm verify   # 191 เคส
cd frontend && pnpm verify   # 169 เคส
cd backend  && pnpm test     # 17 unit test (ตรรกะต้นทุน coverage 100%)
```

ตัวอย่างสิ่งที่ทดสอบ (ไม่ใช่แค่ "ไม่ error"):

- รับ 10 ชิ้น@100 + 10 ชิ้น@200 → ทุนเฉลี่ยต้องเป็น **150** เป๊ะ
- FIFO: รับ 3 ล็อตราคาต่างกัน จ่ายคร่อมล็อต → ต้นทุนต้องเป็น **2,950**
- ยิงจ่าย 50 request พร้อมกัน → ยอดคงเหลือตรงกับจำนวนที่สำเร็จ ไม่ติดลบ
- ขอเลขเอกสาร 30 ใบพร้อมกัน → ไม่ซ้ำ ไม่โดด
- ซื้อ 60@44 + 40@48 ขาย 70 → กำไรต้องเป็น **660** อัตรากำไร **17.46%**
- ยกเลิกใบส่งของ → สต๊อกคืน และ movement เดิม**ยังอยู่**ใน ledger

> ชุดทดสอบสร้างข้อมูลใหม่ทุกครั้งที่รัน รันซ้ำได้โดยไม่ต้องล้าง DB
> ล้างข้อมูลทดสอบที่สะสมได้ด้วย `pnpm db:cleanup`

## ความปลอดภัย

- **รหัสผ่าน** hash ด้วย Argon2id
- **Token** — access 15 นาที + refresh rotation พร้อมตรวจจับการใช้ซ้ำ (ถูกขโมย = ตัดทั้ง session family)
- **หน้าเว็บไม่เคยเห็น token** — เก็บใน httpOnly cookie แล้วให้ Next.js เป็นตัวกลางแนบให้ (โดน XSS ก็ขโมยไม่ได้)
- **RBAC ทุก endpoint** — ซ่อนปุ่มที่กดไม่ได้ในหน้าเว็บ และกันจริงที่ backend อีกชั้น (ยิง API ตรงก็ไม่ผ่าน)
- **ตรวจ input ทุกชั้น** — `ValidationPipe` ตัด field แปลกปลอมทิ้ง กัน mass assignment
- **helmet · rate limit · CORS whitelist**
- **ไม่มี hard delete** — สินค้า/คู่ค้าใช้ปิดใช้งาน เอกสารใช้ยกเลิก ledger ใช้กลับรายการ
- **API secret ไม่หลุดหน้าบ้าน** — รูปอัปโหลดตรงไป Cloudinary ด้วยลายเซ็นที่ backend เซ็นให้

> `.env` และใบรับรองอยู่ใน `.gitignore` แล้ว — ตรวจก่อน push เสมอว่าไม่มี secret ติดไป

## หมายเหตุก่อนใช้งานจริง

ระบบยังอยู่ในขั้น development — ก่อนขึ้นใช้งานจริงต้องทำเฟส 8 ให้ครบก่อน โดยเฉพาะ:

- เปลี่ยน `JWT_SECRET` และรหัสผ่านทั้งหมด · ใช้ DB user สิทธิ์ต่ำสุด · ไม่เปิด DB ออกอินเทอร์เน็ต
- **สำรองข้อมูลอัตโนมัติและทดสอบกู้คืนจริงทุกเดือน** (backup ที่ไม่เคย restore = ไม่มี backup)
- ตั้ง log + แจ้งเตือนเมื่อระบบล่มหรือ reconcile พบยอดเพี้ยน
- รันหลาย instance ต้องปิด cron (`CRON_ENABLED=false`) แล้วย้ายไป job queue ที่มีตัวล็อกกลาง
